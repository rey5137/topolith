# 20 — Architecture and ownership checks

This file specifies descriptor-driven boundary checks, their frozen baseline and startup ownership checks.
It routes work on `TopolithArchitecture.verify()` and non-internal module ownership.

## Rules

### R-ARCH-01 — Contract-only access

`TopolithArchitecture.verify()` derives rules from descriptors: a module accesses another only through its API and
declared `requires` or `optional`, and required dependencies cannot form cycles. Checks fail by default. Implements
INV-4, INV-5, P-4 and D-4.

- AC-ARCH-01 (M3.1): Cross-module access to a non-API type fails, and access to a declared API passes.
- AC-ARCH-02 (M3.1): Access without a declared required or optional dependency fails.
- AC-ARCH-03 (M3.1): A required-dependency cycle fails the architecture check.
- AC-ARCH-04 (M3.1): Access to the API of a declared optional dependency passes.

### R-ARCH-02 — Contract types

Contract signatures cannot expose `Page`, `Stream`, entities, `InputStream` or lazy proxies. The descriptor's API
packages identify the contract types to check. Implements INV-5 and INV-6.

- AC-ARCH-05 (M3.1): A fixture for each prohibited contract type fails the architecture check.
- AC-ARCH-06 (M3.1): A contract using value types passes the contract-type check.

### R-ARCH-03 — Frozen baseline

An adopted repo can freeze existing architecture violations; new violations fail and the baseline only shrinks.
Baseline tooling generates `META-INF/topolith/baseline/<id>.txt` in the referencing module from the frozen ArchUnit
store. Each violation occupies one line in the format `<referencing class FQN> -> <referenced class FQN>`; blank lines
and lines starting with `#` are ignored. Implements P-4, D-4 and D-25.

- AC-ARCH-07 (M3.2): Existing frozen violations pass, while a new violation fails.
- AC-ARCH-08 (M3.2): Removing a violation shrinks the frozen baseline; it cannot grow to accept a new violation.
- AC-ARCH-14 (M3.2): Baseline tooling generates the module's classpath resource from its frozen ArchUnit store with
  one frozen violation per line in the specified format.
- AC-ARCH-15 (M3.3): Startup reads a baseline file generated by the M3.2 tooling and passes its frozen violations,
  ignoring blank lines and `#` comments.

### R-ARCH-04 — Startup ownership

The startup check applies R-VAL-02 to declaring classes and resources. The only startup reference check is R-ARCH-05;
the remaining dependency rules stay in ArchUnit. Implements INV-2 and D-7.

- AC-ARCH-09 (M3.3): A non-internal module's declared bean or auto-configuration fails with TL0007 naming its source.
- AC-ARCH-10 (M3.3): A bean not declared by a non-internal module does not fail solely because of its type.

### R-ARCH-05 — Startup cross-module access

At startup, a class of one internal module referencing a non-API class of another module fails with TL0012 naming
both classes unless the violation is in the D-4 frozen baseline. Descriptors identify module and API packages.
The check reads the referencing module's packaged `META-INF/topolith/baseline/<id>.txt` classpath resource generated
under R-ARCH-03 to identify frozen violations. Implements INV-4, INV-5, P-4, D-17 and D-25.

- AC-ARCH-11 (M3.3): An unfrozen internal-to-non-API class reference fails with TL0012 naming both classes.
- AC-ARCH-12 (M3.3): A cross-module access frozen in a baseline resource inside a packaged JAR passes startup.
- AC-ARCH-13 (M3.3): An internal class referencing another module's API does not fail this startup check.
