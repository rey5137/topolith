# 20 — Architecture and ownership checks

This file specifies descriptor-driven boundary checks, their frozen baseline and startup ownership checks.
It routes work on `TopolithArchitecture.verify()` and non-internal module ownership.

## Rules

### R-ARCH-01 — Contract-only access

`TopolithArchitecture.verify()` derives rules from descriptors: a module accesses another only through its API and
declared `requires` or `optional`, and required dependencies cannot form cycles. Checks fail by default. Implements
INV-4, INV-5, P-4 and D-4; owner resolution and the API shape are D-56.

- AC-ARCH-01 (M3.1): Cross-module access to a non-API type fails, and access to a declared API passes.
- AC-ARCH-02 (M3.1): Access without a declared required or optional dependency fails.
- AC-ARCH-03 (M3.1): A required-dependency cycle fails the architecture check.
- AC-ARCH-04 (M3.1): Access to the API of a declared optional dependency passes.

### R-ARCH-02 — Contract types

Contract signatures cannot expose `Page`, `Stream`, entities, `InputStream` or lazy proxies (the exact name-based list
is D-56). The descriptor's API packages identify the contract types to check. Implements INV-5 and INV-6.

- AC-ARCH-05 (M3.1): A fixture for each prohibited contract type fails the architecture check.
- AC-ARCH-06 (M3.1): A contract using value types passes the contract-type check.

### R-ARCH-03 — Frozen baseline

An adopted repo can freeze existing architecture violations; new violations fail and the baseline only shrinks.
Baseline tooling generates `META-INF/topolith/baseline/<id>.txt` from the frozen ArchUnit store, into an output
directory that holds the referencing module's descriptor, or, given module ids, for the named modules into any
directory such as `src/main/resources` (D-63). Each violation occupies one line in the format `<referencing class FQN> -> <referenced class FQN>`; blank lines
and lines starting with `#` are ignored. Implements P-4, D-4 and D-25.

- AC-ARCH-07 (M3.2): Existing frozen violations pass, while a new violation fails.
- AC-ARCH-08 (M3.2): Removing a violation shrinks the frozen baseline; it cannot grow to accept a new violation.
- AC-ARCH-14 (M3.2): Baseline tooling generates the module's classpath resource from its frozen ArchUnit store with
  one frozen violation per line in the specified format. Given module ids it writes only the named modules into any
  directory, deletes only their stale files, and throws on an unknown id.
- AC-ARCH-15 (M3.3): Startup reads a baseline file generated by `TopolithBaseline.generate` from the root that holds
  the module's descriptor, or from a directory root that holds no module descriptor, and passes its frozen violations,
  ignoring blank lines and `#` comments. A copy in a JAR that is not the descriptor root, in another module's
  descriptor root, or a second accepted copy fails TL0030 naming both (D-63). A baseline frozen by `verifyFrozen` and written by `generate` for a fixture with every
  covered reference kind lets startup pass, and a new unfrozen reference fails TL0012 naming only that pair.
- AC-ARCH-16 (M3.3): A malformed packaged baseline fails startup with TL0030 naming its resource and bad line.

### R-ARCH-04 — Startup ownership

The startup check applies R-VAL-02 to declaring classes and resources. The only startup reference check is R-ARCH-05;
the remaining dependency rules stay in ArchUnit. A non-internal module also contributes nothing through the host's
servlet-component and configuration-properties scans or through the management auto-configuration imports and the
ignored `spring.factories` auto-configuration key (D-61). Implements INV-2, D-7 and D-61.

- AC-ARCH-09 (M3.3): A non-internal module's declared bean or auto-configuration fails with TL0007 naming its source.
- AC-ARCH-10 (M3.3): A bean not declared by a non-internal module does not fail solely because of its type.
- AC-ARCH-21 (M3.3): A host servlet-component scan covering a non-internal module fails TL0007.
- AC-ARCH-22 (M3.3): A host configuration-properties scan covering a non-internal module fails TL0007.
- AC-ARCH-27 (M3.3): A non-internal module class listed in management imports fails TL0007 naming the resource when management auto-configuration is present, even without main-context registration.
- AC-ARCH-34 (M3.3): A non-internal module entry in the ignored spring.factories auto-configuration key leaves no module bean.

### R-ARCH-05 — Startup cross-module access

At startup, a class of one internal module referencing a non-API class of another module fails with TL0012 naming
both classes unless the violation is in the D-4 frozen baseline. Descriptors identify module and API packages.
The check reads the referencing module's packaged `META-INF/topolith/baseline/<id>.txt` classpath resource generated
under R-ARCH-03 to identify frozen violations. It scans only the class-path root that holds the module's
descriptor (D-63). It reads the baseline from that root or from a directory root with no module descriptor (a resource
directory, development runs only; a packaged JAR or fat JAR accepts only the descriptor root); a second accepted copy
fails TL0030 and copies are never merged. Other JARs are neither scanned nor read for baselines, and a module spanning several
main roots has only its descriptor root scanned at startup (ArchUnit covers the rest). Implements INV-4, INV-5, P-4, D-17 and D-25.
The startup check records the same dependency kinds as the ArchUnit non-API rule (R-ARCH-02): field, parameter, return
and `throws` types, generic type arguments, annotations and their values, super types, the owner of each field access
and method call, `instanceof`, class literals, method-reference and lambda targets, and catch types. Neither side checks
the signature types of a called member, the type of an accessed field, casts, array creation or inlined constants.
`BoundaryParityTest` compiles one class per kind and keeps the two sets equal.

- AC-ARCH-11 (M3.3): An unfrozen internal-to-non-API class reference fails with TL0012 naming both classes.
- AC-ARCH-12 (M3.3): A cross-module access frozen in a baseline resource inside a packaged JAR passes startup.
- AC-ARCH-13 (M3.3): An internal class referencing another module's API does not fail this startup check.
- AC-ARCH-17 (M3.3): An annotation-only reference to another module's non-API type fails with TL0012.
- AC-ARCH-18 (M3.3): A registered bean declared in a non-internal module's resource fails TL0007 naming it.
- AC-ARCH-33 (M3.3): An annotation class value referencing another module's internals fails TL0012.

### R-ARCH-06 — Topolith dependencies in module code

Module code may depend on Topolith only through its annotation and contract packages; any other Topolith dependency
fails the ArchUnit check, so business code cannot branch on topology. Implements INV-1 and D-59.

- AC-ARCH-19 (M3.3): A module dependency on Topolith outside annotation and contract packages fails ArchUnit.
- AC-ARCH-20 (M3.3): A module dependency on the Topolith contract package passes this rule.

### R-ARCH-07 — Host scans and auto-configuration back-off

A host scan that covers an internal module's classes fails TL0018, and an internal module bean that makes an
auto-configuration back off (a missing-bean or default-candidate condition) fails TL0031, except persistence beans,
which fail TL0019 alone. A `none` module and a non-default candidate never trigger either. Implements INV-4 and D-60.

- AC-ARCH-23 (M3.3): A host component scan covering an internal module fails TL0018.
- AC-ARCH-24 (M3.3): A host servlet-component scan covering an internal module fails TL0018.
- AC-ARCH-25 (M3.3): A host configuration-properties scan covering an internal module fails TL0018.
- AC-ARCH-28 (M3.3): An internal module default candidate that causes an auto-configuration to back off fails TL0031.
- AC-ARCH-29 (M3.3): A non-default candidate does not trigger TL0031.
- AC-ARCH-30 (M3.3): A none module does not make an auto-configuration back off.
- AC-ARCH-31 (M3.3): A module bean of a type not conditioned on by auto-configuration passes.
- AC-ARCH-32 (M3.3): Persistence beans that make auto-configuration back off fail TL0019 without TL0031.
- AC-ARCH-35 (M3.3): A module bean making a class-level missing-bean condition back off fails TL0031.

AC-ARCH-26 is retired: it was never defined, and the id is not reused because tests carry the ids.
